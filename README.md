## 2) جرّبها في دقيقة (سلسلة مقترحة)

1. **البحث بالعامية** — في الصفحة الرئيسية اكتب: `عايز سماعة JBL تحت 3000 جنيه قريبة مني`
   → شاهد كيف تظهر الفلاتر المُستخرجة تلقائيًا **قبل** البحث (المنتج / الماركة / أقصى سعر / قريب مني).
2. **التحليل الذكي** — صفحة النتائج تفتح بملخص وصفي + «✨ توصية سوقي» بأسباب واضحة لكل خيار (أرخص / أقرب / خصم / متجر موثق).
3. **مقارنة الأسعار** — اضغط `☰ جدول` لترى كل المتاجر في جدول واحد، ورتّب بالضغط على أي عمود.
4. **صفحة المنتج** — افتح أي منتج ← تبويب `📊 تاريخ السعر` (12 شهرًا) و`🗺️ الخريطة` (خريطة رادار بالمتاجر حولك).
5. **المتاجر القريبة** — صفحة الخريطة: جرّب النطاقات من **500 متر** حتى **100 كم**، وفلتر «مفتوح الآن».
6. **ماذا أشتري؟** — من القائمة: `المساعد` ← اكتب `عندي 10000 جنيه وعايز حاجة مفيدة للبيت` أو اختر «رحلة شراء (تجميعة)».
7. **لوحة تحكم المتجر** — اختر متجرًا، عدّل سعر أي منتج واضغط 💾 حفظ: يتحدث السعر في البحث فورًا، ويُسجَّل في سجل التغييرات، وتتحول حالة البيانات إلى «محدث الآن».
8. **لوحة الإدارة** — بلاغات المستخدمين، توثيق المتاجر، وطلب تحديث الأسعار من المتاجر المتأخرة.
9. **📋 وحدة تسجيل المحلات** — 8 خطوات كاملة: هوية المحل والنشاط ← الموقع الدقيق على خريطة تفاعلية ← الفروع والتوصيل ← التواصل ومواعيد العمل أسبوعيًا ← الدفع والخدمات ← البضاعة (4 طرق إدخال) ← الصور والمستندات ← المراجعة والنشر. مع **معاينة مباشرة** للمحل + **مؤشر اكتمال البيانات** + تنبيه بالحقول الناقصة. المحل الجديد يُنشر **فعليًا** ويظهر في البحث والدليل.
   - جرّب بسرعة: اضغط **🎲 املأ البيانات تلقائيًا** ثم تنقّل بين الخطوات، وفي الأخير **🚀 إرسال ونشر المتجر**.
   - **تعديل محل موجود:** من أي صفحة محل اضغط «صاحب المحل؟ استكمل البيانات» أو من لوحة التحكم «✏️ تعديل بيانات المحل» — التعديل يُحدّث الأسعار فورًا ويُسجَّل في سجل التغييرات.
10. **🏬 دليل المحلات** — صفحة مستقلة لكل المحلات المسجّلة مع بحث بالاسم/المنطقة/المنتج، فلاتر (موثق / احترافي / جديد / مفتوح الآن)، جدول كامل بمؤشر **اكتمال البيانات** وحالة موثوقية الأسعار لكل محل.

> 💡 اضغط شريحة **«ℹ️ بيانات تجريبية»** في الهيدر لمعرفة ما هو حقيقي وما هو توضيحي.

## 3) ما هو حقيقي في النموذج وما هو توضيحي

| ✅ حقيقي (منطق فعلي يعمل) | 🟡 توضيحي (بيانات/خدمات لم تُربط بعد) |
|---|---|
| **وحدة تسجيل المحلات كاملة** (8 خطوات + تحقق + نشر فعلي + تعديل لاحق + سجل تغييرات) | **رفع الملفات الحقيقي** (الصور والمستندات تُعلَّم كمُضافة في النموذج، والربط بـ Storage في النسخة الحقيقية) |
| **الخريطة التفاعلية لاختيار الموقع** (سحب، تكبير، عجلة الفأرة، حفظ الإحداثيات) | تحليل ملفات Excel الحقيقية (النموذج يقرأ CSV/النص المنسوخ فعليًا) |
| **استيراد البضاعة**: لصق قائمة من واتساب وتحليلها + قالب CSV جاهز للتحميل | واتساب API لتأكيد الرقم وإشعارات مسؤول الأسعار |
| محرك فهم اللغة العربية (عامية + تشكيل + أرقام عربية + ميزانية + مسافة + حالة المتجر) | بيانات المتاجر والمنتجات والأسعار (44 متجرًا، 72 منتجًا، 417 سعرًا) — أُنشئت لتحاكي السوق المصري |
| حساب المسافات (هافرساين) من إحداثيات حقيقية لمناطق مصر | الاتصال بـ واتساب / الاتصال الهاتفي / تطبيق الاتجاهات (محاكاة + فتح روابط حقيقية) |
| «مفتوح الآن» محسوب من مواعيد العمل المسجلة (بما فيها مواعيد ما بعد منتصف الليل والجمعة) | تنبيهات الأسعار والبريد/الواتساب (تُحفظ محليًا وتُعرض كمتحققة/منتظرة) |
| الترتيب الذكي (سعر/مسافة/خصم/تقييم/حداثة بيانات) + توصية بأسباب | التقييمات والاشتراكات والإعلانات وقائمة «الأكثر بحثًا» |
| تحديث الأسعار من لوحة المتجر → يظهر فورًا في كل الشاشات + سجل تغييرات | الدفع الإلكتروني والاشتراكات |
| معالج «أضف متجرك» ينشر متجرًا فعليًا داخل النموذج | الصور (أماكن مخصصة للصور الحقيقية بعد الربط بـ Storage) |
| حالة موثوقية البيانات (حديثة / مقبولة / تحتاج تحديث / قديمة) على كل سعر | المستخدمون (تسجيل دخول تجريبي بكود 1234، بيانات محلية على جهازك فقط) |

**لقطة الهوية:** افتح ملف `هوية_سوقي_الالوان.html` لرؤية كل الألوان والمكوّنات في صفحة واحدة.
**فحص التباين:** كل النصوص تحقق معيار WCAG AA (النسب من 4.7:1 إلى 14.8:1) — بما فيها الأزرار الذهبية والشارات والنصوص الخافتة.

## 5ب) وحدة تسجيل المحلات — ما الذي تُدخله بالتفصيل؟

| الخطوة | الحقول |
|---|---|
| **1 · هوية المحل والنشاط** | الاسم، الاسم كما على اللافتة، الكيان القانوني، سنة التأسيس، عدد الموظفين، المساحة، الموقف، **أقسام النشاط (16 قسمًا)**، جمهورك، الوصف (+ زر اقتراح وصف تلقائي)، السجل التجاري والبطاقة الضريبية، جملة (جملة/تجزئة)، شامل الضريبة، شارع رئيسي، قريب من المترو، كلمات التخصص |
| **2 · الموقع والعنوان** | المحافظة، المدينة، الحي/المنطقة، الشارع، رقم العقار، الدور/الوحدة، علامة مميزة، **خريطة تفاعلية (اضغط لتحديد باب المحل + تكبير/سحب + «استخدم موقعي»)**، خط الطول والعرض، أقرب مدينة محسوبة تلقائيًا، رابط خرائط جوجل |
| **3 · الفروع والتوصيل** | جدول فروع غير محدود (اسم، محافظة، منطقة، هاتف، عنوان)، تفعيل التوصيل، نطاق التوصيل بالكم، رسوم التوصيل، الحد الأدنى للطلب، وقت التجهيز، **مناطق التوصيل**، الاستلام من الفرع |
| **4 · التواصل والمواعيد** | هاتف (+هاتف ثانٍ)، واتساب، إيميل، موقع، فيسبوك/إنستجرام/تيك توك، **مواعيد العمل لكل يوم من الأسبوع** (فتح/إغلاق/مغلق/ملاحظة) + زر «تطبيق على الكل» + ضبط الجمعة، ملاحظات رمضان والعيد، متوسط زمن الرد، مسؤول التواصل، **مسؤول تحديث الأسعار (اسم + رقم)** |

| **6 · البضاعة والمنتجات** | جدول منتجات: الاسم، القسم، الماركة، الموديل/SKU، الحالة (جديد/مستعمل/مجدد/طلب مسبق)، **السعر**، السعر قبل الخصم، الكمية، متوفر، الضمان + **4 طرق إدخال**: إضافة صف، منتجات مقترحة من أقسامك بنقرة، **لصق قائمة من واتساب وتحليلها تلقائيًا**، **استيراد ملف CSV/Excel مع قالب جاهز للتحميل** + إجماليات (قيمة مخزون تقديرية، أكبر خصم) + حد الباقة |
| **7 · الصور والمستندات** | الشعار، الواجهة، الداخل، الرفوف، صور المنتجات، رابط فيديو، رمز مؤقت + المستندات: السجل التجاري، البطاقة الضريبية، صورة اللافتة، إثبات ملكية الرقم، بطاقة الرقم القومي (للتوثيق ✔️) |
| **8 · المراجعة والنشر** | ملخص كامل للبيانات + أول منتجاتك + اختيار الباقة (مجاني/احترافي) + رغبات الإعلانات + إشعارات واتساب + **الإقرارات والشروط** → زر النشر |

**ما يراه صاحب المحل دائمًا أثناء التسجيل:** معاينة مباشرة لشكل محلّه في نتائج البحث، ومؤشر «اكتمال البيانات %» مع قائمة الحقول الناقصة وزر انتقال مباشر لأي حقل ناقص، وحفظ تلقائي للمسودة على جهازه.

**التحقق قبل السماح بالتالي:** الاسم والأقسام (خطوة 1) · العنوان (خطوة 2) · رقم هاتف صحيح + مسؤول أسعار (خطوة 4) · منتج واحد على الأقل بسعر (خطوة 6) · صورة واحدة على الأقل (خطوة 7) · الموافقة والإقرار (خطوة 8، وتُطلب عند أول نشر فقط). أي منتج بلا سعر يمنع النشر.

## 5ج) Google Places مع Backend آمن — القاهرة والجيزة فقط

### التشغيل المحلي

يتطلب **Node.js 22 أو أحدث**. لا توجد حزم npm خارجية مطلوبة.

```bash
cp .env.example .env
# أضف GOOGLE_PLACES_API_KEY إلى .env محليًا، وليس إلى أي ملف داخل src/.
npm test      # بناء souqi.html واختبارات الواجهة والخادم دون طلبات Google حقيقية
npm start     # يستمع على 0.0.0.0:3000
```

افتح `http://localhost:3000/souqi.html#/nearby` على جهاز التطوير، أو رابط المعاينة/النشر العام.
المتصفح يطلب مسارات نسبية `/api/places/*`؛ لا يستخدم عنوان localhost للوصول إلى API من جهاز المستخدم.
**فتح HTML مباشرة أو نشره وحده على GitHub Pages لا يشغّل Google Places.** بقية العرض التجريبي لا تحتاج إلى الخادم.

### إعداد Google Cloud

1. أنشئ مشروعًا وفعّل **الفوترة** و**Places API (New)**.
2. أنشئ مفتاحًا مخصصًا للخادم، وقيّد APIs المسموحة إلى **Places API (New)** فقط.
3. قيّد المفتاح بعناوين **IP الخروج الثابتة للخادم**، وليس HTTP referrers. في بيئات الخروج المتغيّر استخدم بوابة خروج ثابتة للإنتاج.
4. أضف المفتاح في `GOOGLE_PLACES_API_KEY` داخل `.env` محليًا أو مدير أسرار منصة الاستضافة. لا ترسله في المحادثة ولا تضعه في HTML/JavaScript أو Git؛ `.env` مستبعدة من Git.
5. ضع حصص استخدام مناسبة وتنبيهات تكلفة في Google Cloud. حقول الهاتف والمواعيد قد تؤثر في فئة الفوترة؛ راجع تسعير Places قبل الإطلاق.
6. في الإنتاج اضبط `NODE_ENV=production` و`APP_ORIGINS=https://your-domain.example`، ووفّر HTTPS (مطلوب أيضًا لإذن الموقع). يمكن إدراج عدة origins مفصولة بفواصل. عيّن `PORT` عند الحاجة.

الخادم يعمل دون مفتاح لعرض الواجهة، لكن البحث يعيد `503 / PLACES_NOT_CONFIGURED` برسالة عربية واضحة. لا توجد نتائج وهمية أو عودة تلقائية إلى OpenStreetMap عند الفشل.

### تجربة البحث

- في «المتاجر القريبة» اختر منطقة مثل **مدينة نصر / الدقي / الشيخ زايد** أو اضغط «استخدم موقعي».
- ابحث بالاسم/النشاط ثم اضغط **بحث** أو Enter. تُرسل الكلمة إلى Google؛ لا نكتفي بالفلترة النصية لنتائج قديمة.
- اختر نطاقًا بين **300 متر و25 كم**. فلتر القسم و«مفتوح الآن» يعملان على النتائج الحالية محليًا.
- حد Google المستخدم **20 نتيجة لكل طلب**. لا تعني النتيجة الفارغة عدم وجود محلات: قد تكون هناك نتائج خارج النطاق، أو بلا محافظة موثوقة، أو مستبعدة بالفلاتر. لا ندّعي حصر كل المحلات أو ننفّذ pagination مكلفة تلقائيًا.
- مصدر الاسم والعنوان والهاتف والمواعيد هو **Google Maps**. الأسعار يسجّلها المستخدمون فقط ولا تُستنتج من Google.

### كيف يُفرض النطاق؟

`server/places.js` يتحقق من المدخلات ويحدد نطاق البحث، ثم يفحص **كل نتيجة**:

1. `country.shortText` يجب أن يكون `EG`.
2. `administrative_area_level_1` يجب أن يطابق القاهرة أو الجيزة بقائمة أسماء عربية/إنجليزية محددة.
3. الإحداثيات صالحة وداخل إطار الاستعلام، والمسافة المحسوبة بـ Haversine لا تتجاوز النطاق المطلوب.
4. النتائج بلا محافظة/دولة مؤكدة تُرفض، وكذلك الأنشطة غير التجارية والمحلات المغلقة نهائيًا والتكرار حسب Place ID.

المستطيل الجغرافي الأولي **ليس حدًا إداريًا**؛ لا نعتمد عليه وحده، ولا نطابق كلمة «القاهرة» في اسم المحل/العنوان. لذلك لا تدخل القليوبية أو العبور أو شبرا الخيمة لمجرد قربها من القاهرة. المناطق المكتوبة يدويًا تخضع لنفس تحقق الدولة والمحافظة. الحصر يعتمد على صحة تصنيف Google الإداري، وليس على ملف حدود حكومي مستقل.

### API

| المسار | جسم الطلب JSON | الاستجابة |
|---|---|---|
| `POST /api/places/search` | `{"lat":30.0459,"lon":31.2405,"radiusKm":3,"keyword":"صيدلية"}` | `items`, `source`, `scope`, `limit` |
| `POST /api/places/area` | `{"q":"الدقي"}` | `lat`, `lon`, `where` داخل المحافظتين |

الكلمة اختيارية؛ بدونها نستخدم Nearby Search، ومعها Text Search بقيود موقع، ثم نفلتر إداريًا وفي دائرة المسافة على الخادم. كلا المسارين يرفضان الحقول الإضافية؛ المستخدم لا يستطيع تمرير URL أو FieldMask أو مفتاح خاص به.

صيغة الخطأ: `{"error":{"code":"...","message":"رسالة عربية"}}`.
الأكواد المهمة: `400 INVALID_INPUT`، `422 OUTSIDE_SERVICE_AREA`، `429 RATE_LIMITED`، `503 PLACES_NOT_CONFIGURED`، `502 PLACES_UNAVAILABLE`، `504 PLACES_TIMEOUT`.

### إجراءات الحماية وحدودها

- المفتاح في ترويسة الاتصال **من الخادم إلى Google فقط**؛ لا نعيد أخطاء Google الخام أو نسجل المفتاح/محتوى البحث.
- لا CORS مفتوح؛ تُرفض طلبات المتصفح cross-site، وتُراجع Origin. هذا **ليس نظام تسجيل دخول** ولا يمنع عميلًا غير متصفح من استدعاء API عامة.
- حدود افتراضية: **20 طلبًا/دقيقة/IP، و100 إجمالًا/دقيقة، و4 طلبات متزامنة**، مع `Retry-After`؛ مهلة Google 8 ثوانٍ، وجسم طلب أقصاه 4 KiB، وFieldMask ثابتة.
- `X-Forwarded-For` لا يُوثق افتراضيًا. فعّل `TRUST_PROXY=true` **فقط** خلف proxy موثوق يستبدل الترويسة ويمنع الوصول المباشر إلى الخادم؛ وإلا يمكن تزوير IP. بدونه قد يشترك مستخدمو proxy في حد IP واحد.
- العدادات في ذاكرة **عملية واحدة** وتُصفّر بعد إعادة التشغيل. للنشر متعدد النسخ استخدم حدودًا مشتركة في Redis/API gateway وWAF، مع حصص Google؛ الحماية الحالية ليست ضمانًا ضد إساءة استخدام موزعة.
- الملفات العامة بقائمة سماح فقط؛ لا يمكن تنزيل `.env` أو `.git` أو ملفات `server/`. سياسة CSP تقصر الاتصالات على نفس الأصل، لكن التطبيق القديم ما زال يستخدم inline scripts/handlers؛ ليست هذه إعادة كتابة أمنية لكل الميزات التجريبية.

### إسناد المصدر والتخزين

نعرض **Google Maps** وإسناد مزوّدي البيانات إن أرجعته الخدمة وروابط Google الأصلية. نتائج Google تُعرض كقائمة ولا تُرسم على خرائط SVG التجريبية غير التابعة لـ Google.
بيانات Places لا تُخزّن في `localStorage` أو على الخادم، والاستجابات `Cache-Control: no-store`. تُزال ذاكرة نتائج OSM القديمة عند الإقلاع. أسعار المستخدمين ومنتجاتهم تبقى محفوظة مع **Place ID فقط** دون اسم/عنوان/إحداثيات Google؛ بعد إعادة فتح التطبيق يحتاج المحل إلى بحث جديد لتحديث تفاصيله. أدوات OSM القديمة باقية فقط للتوافق مع سجلات المستخدم السابقة، وليس كمصدر بحث بديل.

قبل الإطلاق العام، راجع شروط وسياسات Google Maps Platform وأضف سياسة خصوصية وشروط استخدام تناسب تطبيقك (الموقع/كلمات البحث تُرسل إلى Google عبر الخادم). لم يُجر اختبار حي بمفتاح في هذا التغيير؛ اختبارات Google تستخدم mocks ولا تتسبب في رسوم.

**البيانات التجريبية**: الجزء السفلي من صفحة «المتاجر القريبة» ما زال عرضًا توضيحيًا منفصلًا لمقارنة الأسعار، وليس جزءًا من نتائج Google أو نطاق الخدمة الحقيقي.

## 6) المعمار التقني

### النموذج الحالي (ما بين يديك)
- **ملف واحد**: `HTML + CSS + JavaScript` خالص، **بدون أي مكتبة خارجية** (لا React، لا Tailwind؛ البحث الحقيقي يستخدم Google Places وقد تترتب عليه رسوم).
- الخرائط: **SVG مرسوم يدويًا** (حدود مصر + النيل + دبابيس) مع تكبير/تصغير وسحب، وخريطة رادار للنطاق المحيط.

## 7) قرارات تصميمية مهمة (مأخوذة من الفكرة الأصلية)

1. **لا يوجد «أفضل متجر» مطلق** — كل ترتيب مرتبط بمعيار يختاره المستخدم (سعر/مسافة/خصم/تقييم/حداثة) + ترتيب ذكي يوازن الجميع.
2. **الشفافية قبل الادعاء** — كل سعر معه عمره الزمني، ووسم 🟢🟡🔴، وتنبيه واضح أن السعر قد يتغير، مع زر إبلاغ في كل مكان.
3. **الذكاء الاصطناعي لا يخترع** — يُستخدم للفهم والمطابقة والترتيب والتلخيص فقط.
4. **المساحات المدفوعة تُعلَّم** — «إعلان · متجر ممول» بشكل صريح، ولا تدخل في الترتيب العضوي.
5. **RTL أصيل** — تخطيط من اليمين لليسار، أرقام واضحة، خطوط عربية حديثة، وأحجام لمس مناسبة للموبايل.

## 9) ملاحظات قانونية وتشغيلية

- **بيانات المتاجر**: تُجمع بإذن صاحب المتجر (نموذج موافقة مختصر داخل خطة الجمع).
- **بيانات المستخدمين**: تطبيق قانون حماية البيانات الشخصية المصري 151/2020 — لا نخزّن موقعًا دقيقًا بدون إذن صريح، ويمكن استخدام «موقع تقريبي» للمدينة.
- **العلامات التجارية**: أسماء المنتجات والموديلات تُستخدم للدلالة الوصفية فقط، والصور تُرفع من المتاجر أو تُستبدل بمصادر مرخّصة.
- **دقة السعر**: كل سعر يُعرض مع تاريخ آخر تحديث + تنبيه «تأكد من السعر عند الزيارة» — هذا يحمي المنصة قانونيًا ويعزز الثقة.

## 10) الخطوة التالية المقترحة

1. اختر **منطقة واحدة** كبداية (مثال: الدقي + المهندسين + العجوزة) — كثافة متاجر عالية ومسافات قصيرة.
2. طبّق خطة جمع البيانات حتى 50 متجرًا موثقًا (10-14 يومًا).
3. استبدل البيانات التجريبية ببياناتهم الحقيقية في نفس النموذج لعرضه على أول متجر — عرض بـ**بيانات حقيقية** يقنع أسرع من أي عرض تقديمي.
4. ابدأ تطبيق الواجهة على Next.js + PostgreSQL بنفس تصميم هذا النموذج.

> جاهز نكمل؟ أقدر أبني أي جزء تختاره بعد كده: هيكل كود Next.js الحقيقي، أو استيراد ملف Excel لمتاجر حقيقية إلى نفس النموذج، أو تصميم شعار وهوية بصرية نهائية لـ SOUQI، أو ملف عرض للمستثمرين.
